2. Spoken structure

Normal disputed subject:

  1. Subject identification
  2. Supporters
  3. Disagreers
  4. Neutral conclusion

Subjects without a genuine disagreement use Subject → Content → Conclusion. Consensus is excluded for now.

Continuity rule: Every component for one subject is composed into one script and rendered in one generation request whenever technically possible. This is intended to prevent shifts in voice, pitch, pace, and tone between clips.

4. Per-subject build record

Each subject must produce a ledger record with:

  • Subject and visible order
  • Research completed and source review completed
  • Script version/hash
  • Requested voice and exact locked profile version
  • Generation attempt count
  • Charon success or failure
  • Studio-Q fallback, if used
  • Archival WAV validation
  • MP3 conversion setting and validation
  • R2 object names and upload results
  • Remote MP3 playback verification
  • Final status: ready, failed, or held for Robert's review

5. Retry and quota rules

  1. Count every generation attempt, including retries.
  2. Retry only the failed subject.
  3. Never regenerate successful subjects merely because another failed.
  4. Before a full build, verify the provider's current quota, reset time, and model pricing.
  5. Maintain enough unused capacity for a reasonable retry reserve.
  6. If Charon remains unsuccessful after the approved retry limit, try Studio-Q for that subject only and disclose it.

6. Validation gates

A subject is not ready until all checks pass:

  • Correct subject and current researched content
  • Correct Supporters/Disagreers terminology
  • No Consensus section
  • No duplicated or missing phrases
  • Natural Charon delivery with stable tone, pace, pitch, and volume
  • Valid archival WAV with nonzero duration
  • Valid MP3 derived from the approved WAV
  • Uploaded R2 objects exist
  • Remote MP3 plays successfully
  • Visitor URL performs retrieval only—no generation call

7. Missing-audio behavior

If the website cannot retrieve the stored MP3, it must:

  1. Stop the current request and clear queued/in-flight playback.
  2. Display “Audio temporarily unavailable.”
  3. Return control to the visitor without freezing.
  4. Never invoke Charon, Studio-Q, a browser voice, or a paid endpoint from the visitor's device.
